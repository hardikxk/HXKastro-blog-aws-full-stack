Start with the reader’s question. MDX is normal Markdown with the option to use HTML and components when the post needs something more expressive.

## A section heading

Use paragraphs, **strong text**, _emphasis_, [links](https://example.com), ordered lists, bullet lists, and footnotes.[^1]

<Note title="A margin note" type="aside">
  Put a `Note` directly after the paragraph, list, figure, code block, or other block it adds context to. It automatically occupies that block’s matching margin row on wide screens, and becomes an inset note on phones.
</Note>

### Code snippets

Astro highlights fenced code during the build. Add a language after the fence and, optionally, a title.

```ts title="example.ts"
export const greet = (name: string) => `Hello, ${name}.`;
```

### Images and GIFs

For a standard image, use Markdown:

![A useful description of the image](/images/example.webp)

For a caption, use the `Figure` component. Figures always stay within the article’s fixed reading measure:

<Figure src="/images/example.webp" alt="Describe what a reader should notice." caption="An optional caption." wide />

GIFs work exactly the same way. Keep them compressed and use a short clip when possible:

![A small animated demonstration](/images/demo.gif)

### Video, audio, and embeds

Native HTML works in MDX. Keep a poster image on videos so the page remains quick to paint.

<video controls preload="metadata" poster="/images/video-poster.webp">
  <source src="/videos/demo.mp4" type="video/mp4" />
  Your browser does not support video.
</video>

You can also use an `iframe` for a sandboxed external demo. Give it a meaningful title and keep the embed only when it adds more than a screenshot would.

### SVGs and diagrams

Use a local SVG as an image:

<Figure src="/diagrams/my-diagram.svg" alt="Diagram description." caption="What the diagram demonstrates." />
